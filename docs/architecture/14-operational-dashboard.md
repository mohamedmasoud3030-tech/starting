# 14 — لوحة التشغيل والتنبيهات (S7)

## الغرض

S7 تحول الصفحة الرئيسية من عدادات تعريفية إلى لوحة تشغيل يومية تجيب بسرعة عن:

- ما المناسبات الموجودة اليوم؟
- ما المناسبات الجاهزة؟
- ما المناسبات التي تحتاج تدخل بسبب الفريق أو المعدات؟
- هل توجد مواد استهلاكية وصلت إلى حد المخزون الأدنى؟
- كيف يفتح المشغل مساحة عمل المناسبة أو يشارك تذكيراً عبر واتساب بسرعة؟

هذه المرحلة **ليست طبقة محاسبية جديدة** ولا تنشئ AR/AP أو دفتر نقدية. مصادر الحقيقة
المالية تبقى كما عرّفتها S6، ومصادر التشغيل تبقى في جداول/دوال S1–S5 الحالية.

## مصادر الحقيقة

- مناسبات اليوم: `events` مع استبعاد `CANCELLED` وباستخدام توقيت `Asia/Muscat`.
- جاهزية المناسبة: RPC القائمة `event_readiness`؛ لا يعاد حساب نقص الفريق أو المعدات في الواجهة.
- تنبيه المخزون: read model القائمة `consumable_stock_summary` عبر طبقة S4B.
- مشاركة واتساب: بيانات المناسبة التشغيلية الحالية فقط (الاسم، الرقم، الموعد، الموقع، عدد الضيوف).

لا تُشارك أسعار أو تكاليف أو هوامش أو مدفوعات في رسالة واتساب.

## فشل الجاهزية

عدم توفر نتيجة `event_readiness` لا يعامل كمناسبة جاهزة. تظهر حالة صريحة
«الجاهزية غير متاحة» وتنبيه يطلب فتح مساحة العمل والمراجعة.

## واتساب

- يستخدم رقم التواصل المسجل في المناسبة.
- الأرقام المحلية العمانية ذات 8 خانات تحول إلى `968XXXXXXXX`.
- الأرقام الدولية تحفظ بعد إزالة تنسيق العرض فقط.
- الرقم غير الصالح لا ينتج رابطاً؛ تعرض الواجهة أن رقم التواصل غير متاح.

## PWA

S7 تضيف manifest وتسجيل Service Worker بسيطاً.

قاعدة الأمن: Service Worker لا يخزن صفحات التطبيق أو ردود Supabase/API. الكاش مقتصر
على static same-origin assets (`script/style/font/image`) فقط حتى لا تصبح بيانات tenant
الحساسة متاحة من cache خارج حدود جلسة المصادقة.

## النطاق المؤجل

- Push notifications من خادم/مزود خارجي.
- جدولة رسائل واتساب آلياً.
- Background sync للكتابات التشغيلية.
- Offline mutation queue.

هذه القدرات تحتاج بنية تسليم/اشتراكات وسياسات retry مستقلة، ولا يتم تمثيلها كمنجزة في S7.
