# نظام إدارة عمليات الضيافة — Hospitality Operations

تطبيق ويب **عربي أولاً** (RTL-first) لإدارة عمليات الضيافة والمناسبات لمكتب خدمات
الضيافة في **سلطنة عُمان**.

يركّز المنتج على حلٍّ واحد: **تحويل طلب العميل إلى مناسبة مغلقة وربحية** — من تسجيل
الطلب، مروراً بالعرض السعري والتأكيد، وحتى تنفيذ المناسبة وإغلاقها وحساب الربح الفعلي.

> هذا المستودع كان سابقاً تطبيق نقاط بيع لمطعم (RestoPOS Pro). تم تحويله بالكامل
> إلى أساس منصة ضيافة، مع الإبقاء على سجل Git كما هو.

---

## الغرض والسوق المستهدف

- **السوق:** شركات/مكاتب خدمات الضيافة في سلطنة عُمان التي تنظّم المناسبات الخاصة
  والعائلية (أعراس، عزاء، مجالس، اجتماعات، إفطار/غداء/عشاء، وغيرها).
- **المستخدم الأساسي:** مالك المكتب (50+ عاماً) — البساطة والوضوح متطلب منتج، وليست
  ترفاً بصرياً.
- **المبدأ المركزي:** **المناسبة (Event) هي محور النظام**. كل ما هو تشغيلي يعود
  في النهاية إلى مناسبة.

## فلسفة المنتج

1. **بساطة قبل كل شيء** — أسهل من Excel والدفاتر ورسائل واتساب.
2. **كل شيء قابل للتسعير والتهيئة** — لا أسعار تجارية مكتوبة في الكود.
3. **سلامة الأسعار التاريخية** — تغيير سعر الكتالوج غداً **لا** يغيّر عروض أو مناسبات
   قديمة (لقطات سعرية Snapshot).
4. **دقة نقدية** — الريال العماني بثلاث خانات عشرية، لا حساب عشري ثنائي (float).
5. **أمن وعزل بين المنظمات** — RLS إلزامي، وليس مجرد حراسة في الواجهة.

## التقنيات (Stack)

| الطبقة | التقنية |
| --- | --- |
| الواجهة | React 19 + TypeScript |
| البناء | Vite |
| التوجيه | TanStack Router |
| حالة الخادم | TanStack Query |
| التنسيق | Tailwind CSS v4 + مكوّنات ui/ مبنية يدوياً |
| قاعدة البيانات | PostgreSQL عبر Supabase (مخطط + RLS + أوامر RPC) |
| المصادقة | Supabase Auth (بدون أي مسار دخول تجريبي) |
| الاختبار | Vitest + React Testing Library (+ pgTAP لقاعدة البيانات) |
| الفحص | oxlint + `tsc --noEmit` |

## الإعداد المحلي

### المتطلبات

- Node.js 18+
- (اختياري للتطوير الكامل لقاعدة البيانات) Supabase CLI + Docker

### الخطوات

```bash
npm ci               # تثبيت التبعيات

cp .env.example .env # ثم املأ قيم Supabase الحقيقية
```

`.env`:

```
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

> لا تضع أبداً مفتاح `service_role` أو كلمة مرور قاعدة البيانات أو أي سر في متغيرات
> `VITE_*` — أي متغير `VITE_*` يُضمَّن في حزمة المتصفح ويكون عاماً.

### الأوامر

```bash
npm run dev         # خادم تطوير (منفذ 3000)
npm run typecheck   # فحص الأنواع
npm run lint        # فحص الأكواد (oxlint)
npm test            # تشغيل الاختبارات (Vitest)
npm run build       # بناء إنتاجي
npm run preview     # معاينة البناء الإنتاجي
npm run db:types    # توليد أنواع Supabase من المخطط المحلي
npm run db:reset    # إعادة تشغيل سلسلة الترحيلات من قاعدة فارغة
```

## سير عمل ترحيلات قاعدة البيانات

الترحيلات في `supabase/migrations/` مرقّمة ومرتبة، وتُطبَّق بالتسلسل من حالة فارغة.

**قواعد صارمة:**

- الترحيل المطبَّق **خالد** — لا تعدّل ملف ترحيل سبق تطبيقه. أي تغيير لاحق يكون
  بترحيل جديد.
- السلسلة يجب أن تعمل من قاعدة فارغة (`supabase db reset`).
- لا تعتمد على تعديل المخطط يدوياً من لوحة تحكم Supabase كمصدر حقيقة.

اختبارات قاعدة البيانات (pgTAP) في `supabase/tests/` وتُشغَّل عبر `supabase test db`.

## الاختبارات

```bash
npm test
```

- **النقود:** ثلاث خانات عشرية، رفض القيم السالبة، التقريب، الضرب الدقيق بدون أخطاء float.
- **الكتالوج:** إنشاء/تعديل/تعطيل صنف، رفض طريقة تسعير غير صالحة، تحقق الملكية.
- **الباقات:** انتماء الباقة للمنظمة، رفض مراجع عابرة للمنظمات.
- **الأمان (pgTAP):** عزل المنظمات، العضوية غير النشطة، الأدوار غير المصرّحة.
- **الواجهة:** نماذج الكتالوج والباقات وحقل المبلغ.

## نظرة على البنية

```
src/
  app/              # مزوّد المصادقة (بدون مسار تجريبي)
  components/
    ui/             # نظام تصميم صغير (أزرار، حقول، حوارات...)
    layout/         # هيكل التطبيق والتنقل
    MoneyInput.tsx  # حقل مبلغ بثلاث خانات عشرية
  features/
    auth/           # تسجيل الدخول
    catalog/        # إدارة الكتالوج التجاري
    packages/       # قوالب الباقات
    customers/      # العملاء
    home/           # الشاشة الرئيسية
  lib/              # عميل Supabase، النقود، الأنواع، الأدوات
  routes.tsx        # تعريفات TanStack Router
supabase/
  migrations/       # ترحيلات المخطط (خالدة ومرقّمة)
  tests/            # اختبارات pgTAP للأمان
docs/architecture/  # وثائق البنية
```
